| 7 | Friction summary | Problems with Kiro features hit so far | | **Hooks load only at session start.** A hook added mid-session doesn't run until Kiro restarts, so hook work needs a restart before it can be tested. **File hooks fire only on agent saves.** Saves in the editor and edits made through the shell don't trigger them, so "save a file and watch the hook" can't be checked by hand. **Writes to `.kiro/settings/` are blocked** for the agent by a permission rule, so the user had to create `mcp.json` by hand from content the agent supplied. **Command-hook output isn't visible to the agent.** To work around this, the helper appends each command, its exit code and the last 20 output lines to `%TEMP%\ghost-ledger-hook-runs.log`, which the agent reads to confirm results. |

| 15 | Hooks (run log) | `%TEMP%\ghost-ledger-hook-runs.log` | 194 hook runs were logged during tasks 8–15, so the agent could read every result. | 15 | Mutation check (the story) | Why 12 of 33 mutants survived, and how the generators were strengthened | At the task 15 checkpoint, every rule had a property test and all tests passed. Breaking each rule on purpose showed that 12 rules were guarded only by example tests. The property tests did run, but their random inputs never reached the case that mattered. A loan principal was a random fraction of the limit, so "limit + 1" never came up. Reversal times were spread over 45 days, so a span of exactly 30 days never came up. Entries ran from 21:00 to midnight, so nothing happened at 06:00. Phone strings were random, so a correctly shaped number that doesn't start with 7 never came up. The fixes: generators biased to exact boundaries (limit ± 1, outstanding ± 1, whole hours and days, 05:00–07:00, names of 29–32 characters, near-miss phone numbers); targeted properties for states random sequences rarely reach (lend most of the cash, then try every reversal; "as of" times next to a real due date); and covering every case on every run (P7 changes every field; every generated group has an outsider and a suspended leader). Final result: 45 mutants, each caught by its own property in 2 of 2 runs. Details are in `docs/MUTATION-CHECK.md`. | The lesson for the hackathon write-up: green property tests don't prove coverage. Only the mutation check showed the gaps. Detection is random, so a mutant caught once can be missed the next run; running each mutant twice found three more weak spots. The check is now `npm run mutation:check`. It edits only a temporary copy, and a guard plus a test stop it from writing real files. |
